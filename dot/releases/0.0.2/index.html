0.0.2

DOT becomes a two-lane instruction package for owner-authorized ingestion by a configured agent: a stable #AGENT contract and a compact #PROJECT → #INTERNET → #DATA → #TEMPLATE research workflow. This release removes redundant live prompt variants while preserving their exact 0.0.1 provenance and public compatibility paths.

Scope

  • Public product: dot/.
  • Source baseline: immutable tag 0.0.1.
  • Current Agent source: dot/agent/.
  • Current Research source: dot/research/.
  • Documentation root: https://devs-guide.github.io/openai/dot/.
  • Source and documentation only; no binary runtime or hosted application.

Highlights

  • Establishes one canonical home for runtime mechanics and one for research.
  • Presents Research left to right as Project, Internet, Data, and Template.
  • Makes browser use the default and cloud-computer tools project-specific.
  • Enforces an explicit accessibility-gated model order with no unlisted model substitution or Codex use.
  • Adds a hash-bound ingestion manifest and receipt-first bootstrap for loading an exact tagged archive into the owner's OpenAI dot.
  • Provides structured Fact, Page, video, transcription, checkpoint, dataset, immutable release, correction, refresh, and delivery contracts.
  • Audits the complete historical corpus in GitHub Actions without local tests.

Added

  • Agent contract, configuration, schema, runtime observations, and browser, Page, and media modules.
  • Project, Internet, Data, and Template prompts with distinct responsibilities.
  • A 22-basename applicable-file catalog with stable grains, typed fields, provenance layers, CSV/JSON parity, review gates, and immutable snapshots.
  • A machine-readable migration ledger and CI-only clause audit artifact.
  • A machine-readable release-ingestion manifest with ordered authority classes, conditional capability modules, hashes, and activation gate.
  • A synthetic paired Fact-view JSON/CSV example inside the Template without adding another examples subtree.
  • Manifest-defined legacy rendered redirects and raw migration pointers.

Changed

  • Replaced dot/agents/ and dot/prompts/ with singular dot/agent/ and dot/research/ lanes.
  • Moved environment facts into dated runtime observations and owner choices into configuration.
  • Replaced the historical model ladder with the owner-approved ORDERED_FALLBACK sequence in Agent configuration.
  • Replaced broad terminal exceptions with browser-first behavior and explicit project allowlists for already-present cloud-computer tools.
  • Extended Pages publication to render JSON sources and compatibility routes.
  • Extended Research navigation and Pages publication to the Data contract and its exact raw source.
  • Distinguished the community DOT package from OpenAI's dot product, and made memory and connected-app context explicitly non-authoritative.

Fixed

  • Removed repeated and scattered browser, evidence, checkpoint, reporting, and research instructions from the live source tree.
  • Separated Agent-owned Page and media mechanics from Research-owned Facts and evidence evaluation.
  • Preserved missing values as null records instead of allowing missing-to-zero conversions.
  • Separated source, document, version, URL, access, assertion, observation, claim, and evidence-link grains; separated derivation, verification, and reviewer type.
  • Required corrections and refreshes to create successor releases rather than mutate an accepted snapshot.
  • Kept exact historical prompt bodies recoverable without publishing a second live archive.

Safety and publication model

The project remains community maintained and is not affiliated with or endorsed by OpenAI. Product facts, owner policies, dated observations, working assumptions, and research Facts are distinct record classes.

The public repository grants no reuse permission. Release ingestion assumes the repository owner or a party with separate written authorization.

The browser is the default research surface. Codex, software installation, coding projects, local-computer execution, unassigned models, and access-control bypasses are prohibited. Existing cloud tools require a project allowlist.

Compilation, migration auditing, builds, and tests run only in GitHub Actions. The local workstation is not a validation environment.
