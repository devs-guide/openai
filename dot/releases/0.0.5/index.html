0.0.5

DOT summaries now complete the material evidence they need instead of merely reformatting whichever Facts were already easy to find. Each requested brief starts with a required Fact matrix, follows relevant public-source paths inside the approved Project boundary, and cannot claim broad coverage while obvious official-site or document routes remain unchecked.

The change preserves the separate, reader-focused PDF deliverable and the four-stage Research workflow. Missing evidence returns through Internet and applicable Data controls, while parent reports and accepted dataset releases remain immutable.

Scope

  • Release range: 0.0.4..0.0.5.
  • Product boundary: DOT's conditional Summary deliverable and the Project, Internet, Data, and Template controls it uses.
  • Published entrypoints: the existing Summary rendered and raw routes, updated Research documentation, and this release record.
  • Included release identity: DOT 0.0.5, prior release 0.0.4, migration baseline 0.0.1.
  • Excluded: executing a real research brief, changing Agent models or permissions, changing BROWSER-004, and attaching generated PDFs or other binary assets.

Highlights

  • Makes bounded public-source gap filling the default for a requested Summary; source-limited synthesis now requires an explicit request.
  • Requires one matrix row per in-scope subject and required fact before design or narrative writing begins.
  • Requires direct official-site navigation, linked-document review, distinct web and PDF discovery, and honest terminal states for unresolved facts.
  • Keeps new evidence traceable without mutating the frozen parent report or an accepted dataset release.

Added

  • A reusable Summary Fact Matrix row with separate work state, coverage disposition, Fact references, evidence references, missingness, reviewer, and next-action fields.
  • Version 2 Executive Brief Request and Completion Receipt structures covering research mode, required facts, entity chapters, evidence-completion gates, coverage denominators, review independence, and optional export parity.
  • Acceptance checks for official navigation, JavaScript search shells, all-entity claims, immutable corrections, and stale Summary drafts.

Changed

  • Advanced the Summary contract to dot-research-summary/2 while retaining SUMMARY-001 through SUMMARY-010 as its stable public rule IDs.
  • Clarified that Summary work may return missing Facts through Internet and applicable Data processing inside the approved Project boundary.
  • Generalized the original education example into reusable entity, source, shared-resource, historical-state, and site-function safeguards while preserving the existing elementary-school compatibility rules.
  • Advanced ingestion, Pages, workflow, feature, and release metadata to 0.0.5, with 0.0.4 as the immediate predecessor.

Fixed

  • Prevented a Summary from treating a blank field, homepage, search snippet, loading URL, inaccessible route, or unexecuted JavaScript search as evidence that a fact does not exist.
  • Prevented attractive formatting, limitations prose, source counts, or a worker's completion label from hiding unfinished material research.
  • Prevented sampling from supporting a claim that every requested entity was checked.
  • Prevented newly discovered Facts from silently changing an accepted parent dataset or leaving requested machine-readable companions out of sync.

Interfaces and compatibility

  • dot-research-summary/2 supersedes version 1 for new Summary activations.
  • dot-executive-brief-request/2 defaults research_mode to PUBLIC_SOURCE_GAP_FILLING; EXPLICITLY_SOURCE_LIMITED remains available when the owner deliberately restricts source use.
  • dot-summary-fact-matrix-row/1 is a control view over canonical Facts and evidence. It is not a new Data basename or competing evidence store.
  • dot-executive-brief-completion/2 records matrix coverage, final evidence and dataset versions, review independence, export parity, rendering, delivery, and readback.
  • Historical version 1 requests and completion receipts remain historical records and are not reinterpreted.

Validation evidence

GitHub Actions must verify canonical Summary rule ownership, the new JSON structures and enumerations, official-site evidence-completion clauses, Project scope gates, Data immutability, paired export parity, absence of the retired draft, exact ingestion hashes, rendered and raw Pages routes, release identity, and unchanged Agent configuration and BROWSER-004 behavior.

Known boundaries

  • Gap completion stays within the approved Project scope and permissions. A material change to population, geography, period, evidence universe, destination, or access still requires an approved amendment.
  • A documented barrier or bounded negative search may produce COMPLETE_WITH_GAPS; the contract does not demand impossible proof of absence or authorize bypassing access controls.
  • This release defines and validates the workflow. It does not claim that a later real-world Summary project succeeded.
